---
title: Import a CSV
description: Bring in transactions from any bank's or broker's CSV export, column by column.
---

Use a CSV import for a bank you can't connect, a platform that shows **Coming soon**, or history from before you connected. Your browser reads the file. You check every column before ViteHub Finance saves anything.

## Before you start

- Export your transactions from your bank's website as a CSV. If you have an Excel, ODS, or PDF file, save or export it as CSV first.
- The file can be up to 5 MB. For a longer history, export shorter periods and import them one by one.
- You need an account to import into. Usually that's a [manual account](/docs/guides/connect-accounts#manual-accounts). You can import into any account you can edit, except archived ones.

## Open the import

You can start an import from several places:

- **Accounts** page: **Import CSV**
- **Banks** page, under **Import a CSV**: **Import**
- **Crypto** and **Investments** pages, below the tiles: **Import a CSV**
- A **Coming soon** platform's details: **Import a CSV instead**
- A manual account's own page: **Import CSV**

The dialog is called **Import transactions from a CSV**. It has three steps: **File**, **Columns**, and **Preview**.

## Import step by step

::steps
### Choose the account and the file

Under **Into account**, pick the account the transactions belong to. If you started from an account's page, it's already chosen.

Drop the file on the dialog, or click **Choose a file**. Comma, semicolon, and tab separated files all work, with or without a header row.

No file at hand? Click **Try it with a sample file**. It loads six months of a sample current account.

### Check the columns

ViteHub Finance guesses which column is which from the file. Check each field and fix any that are wrong. [Column mapping](#column-mapping) describes each field.

**Preview** stays disabled until you've chosen a date, an amount, and a description or counterparty.

### Check the preview

The preview shows how many rows are ready, the total **Money in** and **Money out**, and the date range. Below that are the first ten rows as they'll be imported.

The preview marks each row it can't read, with the reason. Those rows are skipped. If many rows are skipped, go **Back** and check the date format and columns.

### Import

Click **Import** with the row count, for example **Import 128 rows**. When it's done, you see how many transactions were added and how many were skipped.
::

## Column mapping

| Field | What to choose |
| --- | --- |
| **Separator** | The character between columns: **Semicolon (;)**, **Comma (,)**, **Tab**, or **Pipe (\|)** |
| **Header** | Turn on **The first row names the columns** if the first row has column names instead of a transaction |
| **Date** | The column with the transaction date. Required. |
| **Date format** | How the dates are written. See [Dates](#dates). |
| **Description** | The column with the transaction text, like "Groceries" or a card payment line |
| **Counterparty** | Optional. The column with the payee or payer. |
| **Amount** | **One column** or **Debit and credit**. See [Amounts](#amounts). |
| **Decimal separator** | **Detect per row**, **Comma (1.234,56)**, or **Point (1,234.56)** |

Each transaction needs a description. If the description is empty, ViteHub Finance uses the counterparty instead. You can map only one of the two.

## Dates

Pick the format your bank uses:

| Format | Example |
| --- | --- |
| DD/MM/YYYY | 31/01/2026 |
| MM/DD/YYYY | 01/31/2026 |
| YYYY-MM-DD | 2026-01-31 |
| DD-MM-YYYY | 31-01-2026 |
| DD.MM.YYYY | 31.01.2026 |

The separator between day, month, and year doesn't have to match the example. A two-digit year counts as 20xx. A time after the date is ignored. A row whose date doesn't fit the format, or isn't a real day, is skipped.

## Amounts

Banks write amounts in two ways. Choose the one that matches your file.

- **One column** is a single signed amount, negative for money out. Choose the column under **Amount column**.
- **Debit and credit** puts money out and money in in separate columns. Choose **Money out (debit)** and **Money in (credit)**. You can leave one of them as **None**.

Some card exports list purchases as positive numbers. With **One column**, tick **Spending shows as positive numbers** to flip every sign.

If the amounts in the preview look wrong, set **Decimal separator** to match your file. For example, choose **Comma (1.234,56)** for a file that writes €1.234,56.

## Duplicates

Rows already in the account are skipped. A row counts as already there when it has the same date, amount, and description as one imported before. Two identical rows in the same file, like two €3.20 coffees on one day, stay two rows.

This means you can import the same file twice, or overlapping exports, without getting doubles.

> [!WARNING]
> Duplicate checks compare against earlier imports. If you import into an account that a bank or other connection syncs, its synced rows may not match the CSV's rows, and the same payment can show up twice. Import into a manual account when you can.

## After the import

- The transactions get categories from your [rules](/docs/guides/categories-and-rules), and moves between your own accounts become transfers.
- ViteHub Finance looks for recurring payments in the new rows. See [Recurring payments and forecast](/docs/guides/recurring-and-forecast).
- ViteHub Finance fills in the account's balance history, working back from its current balance.
- The import doesn't change the account's balance. For a manual account, update it with **Update balance** in the account's settings.

If the import stops partway, import the same file again. Rows already added stay, and only the rest are added.
